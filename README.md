# Factorio专用服务器：按人数选配置、搞定 34197 端口，把异星工厂存档常年挂着跑

Factorio 服务端要不要单独租一台机器，取决于你受够了什么。

最常见的触发点是这样：今晚谁在线谁开主机。存档绑在别人作息上，主机一关工厂停摆；主机一边渲染游戏一边跑模拟，重基地的 UPS 掉下去，全队一起变慢；有人想中午进去铺两条传送带，发现房主上班去了。

还有一个很反直觉的事实：**异星工厂的模拟基本是单线程的**。多核心只在生成地图、加载存档这类环节帮得上忙，真正决定 UPS 的是单核主频和 IPC。所以「32 核大机器」在这里不是答案，一台单核强、内存够、有公网 IP 的小机器反而更划算。

下面把选配置、选线路、开服步骤和容易踩的坑一次说清楚。

## 先回答三个问题，配置就定了一半

不用纠结具体型号，先算清楚这三件事。

**1. 同时在线人数**

2 GB 内存能撑 1–4 人，5–12 人往上走到 4 GB，超过 12 人建议 8 GB 起步。这是各家托管商给出的一致口径，也是比较保守的估法——纯原版、基地不大的存档，1 GB 也能跑起来（ConoHa 的官方镜像就标了最低 1024 MB），但那个数字没给你留任何余量。

**2. 用不用 mod，用多少**

mod 是内存杀手。内容型大 mod（比如各种 overhaul）不只是多占内存，还会让模拟帧时间变长，间接推高单核压力。用 mod 的话，在同人数基础上直接上浮一档。

**3. 存档多大、跑了多久**

Factorio 的自动保存是阻塞式的：进度越往后，一次 `server-save` 的停顿越明显。这是硬盘 IO 和单核性能共同决定的，跟核心数关系不大。所以真正影响体验的硬件维度是「单核强不强 + 硬盘是不是 NVMe」。

对照表大致是这样：

| 场景 | 建议配置 | 说明 |
| --- | --- | --- |
| 2–4 人，原版新档 | 2 核 / 4 GB | 入门档足够，10M 上行够用 |
| 5–10 人，原版，中后期基地 | 4 核 / 8 GB | 单核频率比核心数重要 |
| 5–10 人，带内容 mod | 4 核 / 8–12 GB | mod 越多内存越紧 |
| 10 人以上或巨型工厂 | 6 核 / 16 GB 起 | 需要高主频旗舰 CPU |
| 长期跑、存档已很大 | 上 NVMe + 固定计费 | 避免自动保存时卡顿影响全队 |

## 自建和托管，差别到底在哪

如果手边正好有一台闲置 Linux 机器，自己搭能省这笔钱——Wube 官方提供免费的 headless 包（只支持 linux64），解压、建存档、起服务，一个下午能弄完。这条路不值得劝退。

但它有几个绕不开的地方：

- 你要在路由器上放通 **UDP 34197**，还要跟 ISP 的 NAT 较劲。
- Factorio 的模拟是单线程的，在你玩游戏的那台机器上同时跑服务端，客户端和服务端会抢同一个核，基地一大就体现在 UPS 上。
- 每次官方发新版本，你得手动拉包更新。

托管服务器的价值就在这几处：机器 24 小时在线，不跟你抢 CPU，更新在面板上点一下。对「工厂必须持续增长」这件事来说，主机离线的那几个小时恰恰是最难受的。

## 动态计费和固定计费，怎么算这笔账

游戏云支持两种计费方式，选错方向差别不小。

**固定计费**：按配置一口价，CPU 全速跑，不管占用多少都不额外收费。

**动态计费**：基础费用明显低，但按 CPU 实际使用率额外收「电量费」。电量单价按 CPU 型号分档，E5-2666 v3 最便宜，Ryzen 5900X 居中，9950X / 7950X / 13900K / 14900K 这一档最贵，大致范围在 0.0005 到 0.001 元/电量之间。

结论取决于你的服务器是「一直有人在玩」还是「周末才开」：

- 服务器长期挂着、玩家在线时间长 → 固定计费。模拟一直吃 CPU，动态计费的电量会一直烧。
- 偶尔开一局、每天玩不了一两个小时 → 动态计费更省钱，因为闲置时不产生电量费。

稳妥的做法是先按动态计费开几天，看看自己的实际电量消耗，再决定要不要转固定。雨云提供 **1 元试用一天**（每款产品限一次，配置贵的试用价会高一些），也有 **7 天无理由退款**（每个账号限 3 次），这两条对犹豫的人来说挺实用。

## 从买机器到连进游戏

拿到机器后，流程和在任何 Linux VPS 上开服一样：

1. **系统选 Linux**，Debian 或 Ubuntu 都行，Factorio 的 headless 包只提供 linux64 版本。追求内存占用低就用无桌面环境。
2. **下载服务端**。到 factorio.com 的下载页拿 headless 包，上传到服务器解压。headless 包不含图形和音频文件，也不会链接 Xlib、libGL 这类库，正是为托管环境准备的。
3. **先建存档再起服务**。专用服务器必须有存档文件才能启动，用 `--create` 生成一个初始档，或者把你本地的存档 zip 传上去。
4. **准备配置文件**。复制 `data/server-settings.example.json` 改成 `server-settings.json`，填服务器名、`max_players`、游戏密码。想上官方公开列表的话，还得填 factorio.com 的账号和 token。
5. **放通端口**。游戏走 **UDP 34197**，RCON 走 TCP 27015（要远程管理才需要）。防火墙里放通 UDP 34197 是关键一步，漏了这一步的症状就是「服务器显示启动成功但谁也连不上」。
6. **连进去**。客户端选多人游戏 → 连接到地址 → 输入 `IP:34197`。

想开机自启的话，写一个 systemd service，用单独的非 root 用户跑 factorio，比直接挂在 root 会话里省心。

## 五个容易踩的坑

**NAT 机型的端口映射**。雨云部分游戏云机型是共享公网 IP 的 NAT 方案（比如镇江的 i9-14900K 机型，可开 15 个端口映射；独立公网 IP 要另外加钱，约 200 元/个）。下单前先确认清楚是独立 IP 还是 NAT——NAT 环境下必须做端口映射，而且**要确认映射支持 UDP**，这是开 Factorio 服的硬条件。

**带宽不是越大越好，是够用就好**。Factorio 服务端与客户端之间传的是同步数据，人数不多的话 10M 上行完全够。把钱花在单核频率和 NVMe 上更值。

**自动保存期间卡顿**。`autosave_interval` 默认 10 分钟，存档大了以后每次保存都会让全队顿一下。可以把间隔拉长，或者接受这个节奏——但别指望多核能救，这是单线程的活。

**desync 多半是 mod 版本不一致**。所有玩家的 mod 版本必须和服务端完全一致，尤其是小版本号。出现不同步时先统一 mod 版本，再考虑减少 mod 数量。

**无人在线时游戏会自动暂停**。这是 headless 服务的默认行为，不是故障。如果想让工厂在你下线后继续生产，需要在 `server-settings.json` 里改 `auto_pause`。

## 常见问题

**1 GB 内存能开 Factorio 服务器吗？**
能启动，官方镜像标注的最低内存就是 1024 MB。但基地一旦变大或者加了 mod，内存会很快吃紧，2–4 人的常规玩法还是建议 4 GB 起步。

**一定要买独立公网 IP 吗？**
不一定。同一局域网内玩可以走 LAN；要让外网玩家连进来，就需要一个公网可达的 IP，或者一套能正确转发 UDP 34197 的端口映射。

**国内节点和香港、美国节点怎么选？**
国内节点（宁波、温州、镇江、宿迁等）延迟最低，适合全部玩家都在国内的队伍，多数还带高防。香港节点免备案、三网直连，适合有海外玩家的情况。美国节点带宽大，但国内玩家延迟会明显高一截。

**Windows 能开服吗？**
可以，但没有 headless 包。要在 Windows 上以服务器模式运行完整的游戏二进制文件，资源占用比 Linux headless 高。纯开服的话，Linux 是更轻的选择。

**服务器版本怎么更新？**
重新下载新版 headless 包替换并重启即可。更新前记得备份 `saves` 目录——雨云的产品支持数据备份，重要存档别只留一份。

## 结论

给 Factorio 选服务器，思路和选普通 VPS 不太一样：单核频率 > 核心数，NVMe > 大容量机械盘，公网 IP 和 UDP 端口是刚需，内存按人数和 mod 量估算。

- 2–4 人原版，预算优先 → 游戏云 E5 或 Gold 6146 入门档，或者美国云服务器中配版。
